# i18n.md — Documentation internationalisation / localisation

> Covers the three observed README i18n patterns across audited repos (mechanical locale-sync, single-source manifest projection, language-selector badge parity), cross-lingual drift detection via `indexion plan drift`, and the stale-path failure mode where translated instructions hardcode a pre-transfer repo owner. Plan §1.3 mechanisms #7, #8, #13; gap G6.

## When to use / When NOT to use

**Use when** the README is the product (archetype A doorway or B skills-pack) and you serve a multi-language audience, or the docs site has locale directories that must track an English source without hand-copying.

**Do NOT use** when the README is a curated list (C) or learning resource (D) where the English README *is* the data and translation adds no navigation value; or when only one locale exists and the sync-workflow cost exceeds the readership.

> This axis is orthogonal to `oss-project-types.md`, which classifies by technology shape (cli-go, library-python, operator, helm) — see plan §4.1a lines 303–307. A doorway-typed operator chart is normal; a multilingual curated list is not.

## The mechanism

Three patterns were observed across the 11 audited repos:

| Pattern | Repo | Mechanism | File | Scale |
|---|---|---|---|---|
| (a) Mechanical locale sync | opencode | GitHub workflow keyed off English source paths | `.github/workflows/docs-locale-sync.yml` | 20 translated root READMEs + 17 docs locales ≈ 560 pages keyed off `packages/web/src/content/docs/*.mdx` |
| (b) Single-source manifest | deepseek-harness | VitePress `docs.ts` projecting one markdown source to many locales | `website/docs.ts` | ~96 canonical pages, ~190 routes; en+zh never drift by copy-paste |
| (c) Language-selector badges | hermes | shields.io `style=for-the-badge` badges with native-language names | `README.md` badge row | 3 READMEs: `README.zh-CN.md`, `README.ur-pk.md`, `README.es.md` |

### (a) Mechanical locale sync — opencode

The workflow (`docs-locale-sync.yml`) does not translate content; it syncs file structure and keys from the English source tree so locales track by machinery, not by hand. The source layout is `packages/web/src/content/docs/*.mdx` — Astro Starlight (plan §1.1 line 22: opencode framework "astro starlight"). The workflow triggers on changes to source `.mdx` files and ensures every locale directory receives the same file skeleton.

Evidence: plan §1.3 mechanism #7 (line 75); gap G6 "opencode 20 READMEs + 17 locales" (plan §1.6 line 155); measured table ~560 doc pages (plan §1.1 line 22).

### (b) Single-source manifest — deepseek-harness

`website/docs.ts` declares `docsPages`, `pairedPages`, `localeCollections`, `mirroredPages` — a single manifest that projects one markdown source to many locales. Because the projection is manifest-driven, en+zh never drift by copy-paste. The measured table shows ~96 doc pages for deepseek-harness (plan §1.1 line 23); the manifest produces ~190 routes.

Evidence: plan §1.3 mechanism #8 (plan §1.3 lines 76–77).

### (c) Language-selector badges — hermes

The root `README.md` (243 lines, 7 badges per plan §1.1 line 21) carries shields.io badges with `style=for-the-badge` and native-language names: **中文** → `README.zh-CN.md`, **اردو** → `README.ur-pk.md`, **Español** → `README.es.md`. Each translated README links to translated CONTRIBUTING and SECURITY variants. The plan's gap G6 records "hermes 3 READMEs" (plan §1.6 line 155).

Evidence: plan §1.3 mechanism #13 (plan §1.3 lines 86–87).

### Cross-lingual drift detection — `indexion plan drift`

The same `plan drift` command used for root-README assembly verification also works on translated README pairs (`README.md` ↔ `README-ja.md`). Vocab sub-tokenization delegates to the natural-language KGFs in `kgfs/natural/`, so cross-lingual drift is detected without a bilingual dictionary. Requires the `indexion` binary (plan §4.1a line 313: "indexion-readme is kept"). Full workflow in `indexion-readme` SKILL.md Step 7.

### Failure mode: stale absolute paths in translations

karpathy ships `README.zh.md` with an `English | 简体中文` toggle at the top (plan §1.3 mechanism #16 attributes `## How to Know It's Working` to karpathy; plan §1.6 line 155 records "karpathy README.zh.md"). The repo now lives at `multica-ai/andrej-karpathy-skills` (plan §1.1 line 19), but the install instructions in the translated README hardcode the **original** owner `forrestchang` in 3 places. Translation/localisation edits are exactly where stale absolute paths hide — the English source was updated to the new owner, but the translated copy was not.

Evidence: plan measured table row `multica-ai/andrej-karpathy-skills` (plan §1.1 line 19); mechanism #16 (plan §1.3 line 92).

## Worked example

**opencode locale sync.** The monorepo root README is 129 lines (plan §1.1 line 22). The locale-sync workflow watches `packages/web/src/content/docs/*.mdx` and ensures all 20 translated root READMEs + 17 docs locales stay structurally aligned. When a new doc page is added to the English source, the workflow creates locale stubs; human translators fill the prose. Mechanical, not generative.

**hermes badge row.** The root README (243 lines, 7 badges — plan §1.1 line 21) carries shields.io badges with native-language names. Clicking **中文** goes to `README.zh-CN.md`; **اردو** to `README.ur-pk.md`; **Español** to `README.es.md`. Each links to translated CONTRIBUTING/SECURITY variants.

**deepseek manifest.** `website/docs.ts` declares locale collections so adding a new `.mdx` source to `docsPages` automatically projects it to every configured locale. No manual file copy needed; en+zh stay in sync by construction.

## What to check before shipping

- [ ] Pick one pattern (a/b/c) — do not mix (a) and (b) in the same repo.
- [ ] For pattern (a): confirm the workflow triggers on the correct source-path glob.
- [ ] For pattern (b): confirm `localeCollections` covers all intended locales; confirm ~96 canonical pages map to expected routes.
- [ ] For pattern (c): confirm every badge `href` resolves to an existing `README.<lang>.md` file.
- [ ] Run `indexion plan drift` on every translated README pair after assembly.
- [ ] Sweep translated files for hardcoded absolute paths (repo owner, org name, import paths) — see the `forrestchang` failure mode above.
- [ ] Confirm the `indexion` binary is available — cross-lingual `plan drift` requires it.
