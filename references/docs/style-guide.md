# README Style Guide

## Common mistakes

- **No install steps** — never assume setup is obvious.
- **No examples** — show, don't just tell. ≥2 runnable blocks.
- **Wall of text** — headers, tables, lists. Paragraphs stay short.
- **Stale content** — internal/config READMEs carry a `Last reviewed` date; everything else gets verified against manifests.
- **Generic tone** — write for the scoping/ audience, not "everyone".
- **Emoji soup** — badges and screenshots carry visuals; prose stays clean.
- **Inlining LICENSE/CONTRIBUTING/CHANGELOG** — link to the dedicated files.
- **Architecture before proof** — screenshots and quick start come first.

## Prose rules

Short sentences. Active voice. Specific nouns over adjectives ("retries 3× with backoff", not "very robust"). Every claim traceable to the mining/ evidence brief — no invented features, versions, or benchmarks.
